# Мониторинг учебных сайтов

Проект модуля 3 курса «Angular и React». На главной странице показано состояние каждого сайта по последней проверке. Карточка ведёт к истории с кодами HTTP, временем ответа и числом успешных проверок. Сводка и страницы сайтов получают данные из общего контекста React.

[Открыть монитор](https://ilpaka.github.io/monitoring/) · [Пример страницы с историей](https://ilpaka.github.io/monitoring/site/chromasync) · [Журнал запусков](https://github.com/Ilpaka/monitoring/actions/workflows/check.yml).

## Что проверяется

В [sites.json](public/data/sites.json) собраны пять опубликованных страниц трёх учащихся группы. Два монитора, LeBron James Ventures, ChromaSync и сайт футбольной секции «Высота» прошли первую проверку 20 ноября 2026 года. У каждого сайта должны быть уникальный латинский `id`, название и адрес. При замене одного сайта другим назначьте новый ID, чтобы история прежнего сайта не оказалась в новой карточке.

## Запуск на компьютере

Нужен Node.js 24. Команды выполняются из корня репозитория.

```bash
npm ci
npm run build
npm run lint
npm run dev
```

Откройте адрес из терминала с путём `/monitoring/`. Для локальной проверки адресов запустите `node scripts/check.mjs`. Результаты попадут в [results.json](public/data/results.json).

## Расписание и оповещения

GitHub Actions запускает проверку по расписанию `0 21 * * *` (00:00 МСК) или вручную через **Actions → Ночная проверка сайтов → Run workflow**. Скрипт сохраняет до 30 последних запусков. Бот GitHub коммитит результаты, затем вызывается процесс публикации на Pages. При переходе по прямой ссылке Pages отдаёт копию приложения из `404.html`, а React Router открывает нужную страницу.

Для отправки сообщений используются секреты репозитория `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Без них результаты всё равно сохраняются и публикуются. Бот сообщает о первом обнаруженном сбое и о восстановлении. Повторяющийся сбой не вызывает нового сообщения.
